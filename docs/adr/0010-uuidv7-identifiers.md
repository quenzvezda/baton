# ADR-0010: Time-ordered UUIDv7 identifiers

- **Status:** Accepted
- **Date:** 2026-10-24
- **Deciders:** @Ripan
- **Spec:** §7 `workflow_runs.id`, §8

## Context

Run and task IDs are generated by several processes, appear in URLs and logs, and are primary keys of
high-insert tables. Random UUIDv4 keys fragment B-tree indexes.

## Decision

Generate entity IDs with `Guid.CreateVersion7()` (built into .NET 9+). Stored as Postgres `uuid`.
`workflow_definitions` keeps a `bigint` identity (low volume, internal). Fencing tokens use a sequence
(ADR-0006), not UUIDs.

## Consequences

**Positive**
- Index-friendly, roughly time-ordered keys; no coordination to generate; cursor paging by id works.

**Negative / risks**
- IDs leak creation time → acceptable; they are not secrets.

## Alternatives considered

| Option | Why not |
| --- | --- |
| UUIDv4 | Index fragmentation on hot insert paths. |
| bigint identity everywhere | Needs a DB round-trip to allocate; IDs guessable/enumerable in URLs. |
